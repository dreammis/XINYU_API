## P1：优先修正影响客户选择和调用的问题

### 1. 图片请求与默认响应示例没有配对

位置：`site/.vitepress/theme/ApiPlayground.vue:17`、`:29`、`:31`、`:110`。

图片生成页当前请求示例包含 `stream: true`、`delivery: "url"`、`progress: true`。请求代码因此使用 `curl -N`。同页默认响应类型却取 `responses[200].content` 的第一项 `application/json`，显示 `{ created, data: [{ url }] }`。

这是前端把两个独立示例并排展示造成的问题。公开契约本身支持 JSON 与 SSE；页面不能暗示开启 stream 后会直接返回普通 JSON。

改法：按真实调用模式组织“普通 JSON”“流式输出”等示例，选中模式时同步选择请求、成功响应类型和对应示例。普通请求作为最小开始路径；流式路径同时展示心跳、可选进度、完成与错误事件。下载的原始规范保持源契约，不为页面展示手改快照。

验收：打开图片接口时，默认请求和默认响应能对应；切换流式后，请求确实开启 stream，响应显示 SSE；`delivery: "url"` 显示 `image_url.completed`，不与 Base64 完成事件混用。

### 2. API 手册需要直接承接模型，而不是再跳一套目录

位置：`scripts/build-site.mjs:99`、`:142`、`:144`。

APIMart 的图片目录能展开 GPT-Image-2，进入该模型的生成页。本站图片目录只有总览、指南、生成和编辑；模型中心则同时展开 10 个图片名称和 4 个视频名称。

生成器当前只把模型逐项放进系列，并没有使用 `model.group` 构造嵌套目录。因此仅补公开清单的 group 字段，导航仍不会自动成为模型分组。

改法：目录组织为“系列 → 已确认的模型组/产品 → 模型说明与适用操作”。模型目录作为筛选入口保留，API 手册也能直接找到模型。共用 HTTP 协议继续只维护一份，模型入口携带明确的模型上下文；不复制 14 份 schema。当前组展开，其他组收起。

分组是公开展示分组，由接入工程确认；不能根据调用名推断原厂身份、实际权重或供应商。

验收：客户从 API 手册侧栏就能找到任一已登记模型及其真实适用操作，进入操作后所选模型不会丢失；目录不会全部展开成长列表。

### 3. 模型页没有把已有的限制直接展示出来

位置：`site/.vitepress/theme/ModelDetail.vue:22`、`:23`；`scripts/build-site.mjs:137`。

`cogvideo-short` 页显示名称、系列、版本，再要求用户点击“先比较能力与限制”。但视频公开指南已经明确记载：仅支持文生、固定 8 秒、720×1280、不支持图生和多参考图。图片指南也已明确 Lite 仅 1K，以及不同路由的 4K 实际像素差异。

改法：当前模型的用途、输入方式、关键限制、调用模式及计费入口直接出现在模型页首屏。来源仍是接入工程的公开清单和指南，文档工程统一生成。通用字段不重新抄一份，模型页只突出差异，并链接到完整协议。

验收：打开 short 页，不再跳转就能读到上述四项限制；打开 Lite 页能直接看到 1K 限制；其他模型只显示源资料确认过的能力。

## P2：继续补齐阅读与分享体验

1. **代码与参数可读性。** `CodeExample.vue:35` 仅输出普通 `<pre><code>`，无语法高亮；`style.css:100` 代码为 11.5px，`:164` 参数说明为 12px，`:167` 约束为 10px。增加语法高亮，提高主要阅读文本字号；将 JSON Schema 的组合条件先解释为客户能理解的条件，再保留完整约束展开。无需增加本产品未支持的参数。
2. **动态接口章节缺锚点索引。** `build-site.mjs:83` 关闭 aside，而 `ApiPlayground.vue` 的鉴权、模型、参数、响应是 Vue 动态标题，不能仅打开 VitePress aside 就认为目录会自动出现。为这些章节设置稳定锚点，提供轻量的章节跳转；普通长指南沿用已有目录。
3. **调试入口距离接口地址较远。** 把主调试入口放到 method/path 行附近，代码区可以保留同一入口。沿用本站 `/api-proxy`、客户 Key 的内存状态和按需加载，保留实际生成计费提示。
4. **模型搜索状态无法分享。** `ModelCatalog.vue:7`、`:8` 的分类和查询仅在组件 ref 中；刷新或分享 URL 不保留筛选。同步到 URL 查询参数。当前没有用途 summary，“图生视频”等任务词也无法靠模型名称匹配，需要接入资料补齐已确认的用途。
5. **首页定位和常用操作入口仍可更明确。** `DocsHome.vue:27` 的“从想法，到第一次调用”没有直接说明产品提供哪些接口；能力卡片只进入系列。首页补充明确定位与生成图片、参考图编辑、创建视频、查询/下载等真实操作入口，让熟悉 API 的客户也能直接到达任务页。
6. **提供 AI 可读取的文档。** 从相同内容生成本站 `llms.txt` 与可公开读取的 Markdown，提供复制页面内容入口。只包含客户文档，不包含内部 SOP、交接材料、渠道配置或凭证。

## DO IT 后的实现与验收（2026-10-10）

上文保留首次检查时的实际问题。三个 P1 和 P2 的阅读、分享及可访问性改进已落实：

- JSON、普通 SSE、URL SSE 和后台调用模式从同一公开 schema 生成，请求与响应类型联动；URL SSE 只展示 image_url.completed。缺失配套响应样例明确标注，不借用其他模式的结果。
- API 手册直接包含当前产品调用名称及适用操作。当前模型展开，其他模型收起；已确认的 group 可生成嵌套组。模型页进入具体接口后保留调用名称，Scalar 初始化也使用当前模式与模型。

- 接口有稳定章节锚点和地址旁的调试入口。手机示例区域入口始终可见，点击章节入口会展开代码，避免跳转到隐藏锚点。
- 模型筛选同步 q/series 到 URL；图生视频关键词只由明确支持的能力行生成，Short 不会被误列入。
- 首页明确图像与视频 API 定位，直接链接八个真实公开操作。新增客户 Markdown、llms.txt 和复制本页，内部 SOP/来源配置/交接记录未进入公开导出。
