# API 同步、异步与流式交付约定

2026-10-12 平台决定：普通 TTS 默认采用同步 `POST /v1/audio/speech`，成功直接返回音频文件；已有异步入口保持兼容。本文件规定交付目标，不能代替真实入口验收。当前 Vox 1 同步接入仍待部署，详见项目审查记录。

## 按客户收到什么区分模式

| 模式 | 请求完成时返回什么 | 客户怎样使用 |
| --- | --- | --- |
| 同步 | 已完成的 JSON 结果或文件 | JSON 解析，或将音频等二进制写入文件 |
| 异步 | 任务 ID 与排队/运行状态 | 保存 ID，查询同一任务，终态成功后取结果 |
| 流式 | 按协议逐步返回事件或媒体数据 | 按对应 Content-Type 消费；终止条件和错误必须明确 |

同步只规定客户一次请求等待结果，上游内部可以使用任务和轮询。JSON 请求并不意味着 JSON 响应。SSE 保活不代表增量语音或视频帧输出；一次最终事件也不能描述为逐字生成。

## TTS 默认客户协议

同步入口为 `POST /v1/audio/speech`。标准字段使用 `model`、`input`、`voice`、`speed`、`response_format`，成功的 MP3 响应使用 `Content-Type: audio/mpeg`，不再包装任务 JSON。只声明已实测支持的输出格式和参数。

New API rc.41 的 AudioRequest 重建请求，只保留它认识的字段。音调、音量、情绪和增强若需要通过该宿主转发，放在它能保留的 `metadata` 对象里，作为本站扩展明确描述；不能把它们放顶层后声称一定生效。新渠道必须沿实际 DTO/适配器验证扩展字段是否保留。

```json
{
  "model": "vox-1",
  "input": "你好，欢迎使用我们的语音服务。",
  "voice": "vx_dbd27c4a9332",
  "speed": 1,
  "response_format": "mp3",
  "metadata": {"pitch": 0, "volume": 0, "emotion": "neutral", "enhance": true}
}
```

自有异步 TTS 入口为 `POST /tts/v1/tasks`，新格式使用相同请求字段、音色、限制、默认值和计费含义。旧 `text`、`parameters`、`output` 格式保留兼容，不能混用两套字段；它不是新的推荐协议。创建响应包含 `id`、`model`、`status`，随后查询同一 ID。

当前自有任务状态为 `queued`、`running`、`succeeded`、`failed`。创建返回 HTTP 200 的排队任务也属于异步，不能看见 200 就当生成成功；当前宿主实际返回 200，不在文档虚构 202。新实现若选择 202，必须实现和规范一致。

## 一致性边界

- 同步与异步统一的是同一能力的输入含义、公开模型/音色、限制、格式和计费结果，不是强行把音频和任务包装成同一种响应。
- 一次客户提交只生成一次，不因查询或下载重新提交、重新计费。按成功生成收费时，断连、超时、失败、退款与音频下载失败各自的账单行为必须实际验证。
- 网络超时不等于任务失败；禁止自动转异步、自动改模型、自动拆文本、自动重复创建。能恢复查询时明确提供既有任务 ID；没有实现恢复时如实说明。
- 多模式接口写明默认模式、选择字段、互斥组合、成功/失败响应和终止规则。不能根据一份请求示例推断另一模式已支持。
- 保留标准协议状态，例如 OpenAI 视频的 `in_progress`、`completed`；自有 TTS 的 `running`、`succeeded` 不同并不自动意味着错误。文档给出对应含义，不破坏标准协议去改名。

## 交付与验收

每个新增能力在指南提供模式表，并用 OpenAPI 的真实成功 Content-Type 描述响应。同步文件响应写 binary schema，不伪造音频 JSON 样例；异步写创建、查询、结果获取三个步骤；流式写真实事件或媒体分块。

同一套正常输入、边界、音色与控制参数分别通过同步和异步实际入口，核对生成行为、错误和账单。只测试 A 或插件 hook 不等于 B 已支持。公开规范和默认导航在入口验收后更新，未部署的候选规范不能登记到 sources.json。

文档站根据成功响应选展示类型，不能把错误响应里的 application/json 当作成功模式。调试器提交一次任务后允许查询和获取结果，绝不重复创建或隐藏任务状态。

## 文档调试登记

异步创建操作在公开 OpenAPI 登记 `x-playground-task`，明确查询 GET、ID 路径参数、合法状态、成功/失败终态，以及可选的产物列表 GET 和下载 GET。参考当前 `media-tts/public-openapi.json` 和 `media-video/public-openapi.json`。Responses 的后台模式还需登记 `when: {"background": true}`，普通模式仍是同步；`stream:true` 则显示为流式。

这个字段是文档站操作指引，不是新增 API 参数，也不改变宿主行为。新接入不能在 Vue 里按模型硬编码一条轮询路径。构建校验查询/下载操作必须已在同一公开规范登记。

流式操作登记 `x-playground-stream` 的 `completed` 和 `failed` 事件名；只能使用已实测或协议明确规定的事件。调试器保留原始 SSE，并按事件边界展示；心跳、`[DONE]`、HTTP 200、连接关闭均不能单独证明生成成功。

当前调试器允许手动查询，或由用户开启每 3 秒自动查询；任务成功、失败、查询错误或关闭面板即停止自动查询。获取音频/视频走已登记的本站代理下载入口，不把客户 Key 转发到任务响应中的任意 URL。请求代码可展开查看，实际结果优先显示。

本地 `npm run dev` 通过 Vite 插件复用 `functions/api-proxy.js`；Cloudflare Pages 使用同一函数。两者共享鉴权、目的地白名单和响应流式处理，不再出现本地只有文档页面、没有调试代理的差异。
