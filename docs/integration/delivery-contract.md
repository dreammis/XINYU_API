# A 向 C 交付什么：项目资料与客户契约

A 的 AI 按本文件直接写到 C 的 projects/<源工程ID>/。模板在 templates/source-project/；只创建真实需要的文件，模板未知项标记待确认，不用空插件假装完成接入。

## 1. 项目身份：README.md 与 source.json

source.json 记录 sourceId、A 本机目录、Git 仓库、研究所用源码版本与未提交状态、原始接口文档路径、已登记能力和 C 内维护位置。README.md 是 C 的入口，解释项目实际功能、已接入范围、待接入项，并链接以下材料。

sourceId 标识源工程；capabilityId 标识公开客户协议；pluginKey 标识 B 的插件；channelId 标识某个运行渠道。四者不能混为一个 ID。稳定源工程 ID优先用实际仓库名。C 的 sources.json 专门登记公开文件，不是 G:/workspace 所有工程清单。

## 2. 上游说明：upstream/api.md

必须让不认识 A 的 C 维护者能理解：
- A 提供什么，本次接入与未接入范围；源码/部署版本和核对日期。
- 每条实际方法、路径、鉴权方式（占位符）、输入格式、参数/默认值/限制。
- 最小成功示例、响应/错误、提交/查询/下载流程、流式与恢复行为。
- 支持的模型/功能、真实区别、批量与部分成功、幂等/重试的已知边界。
- 与拟定客户协议的差异，转换发生在哪里；依赖的配套服务。
- 原始 A 文档/代码位置与验证证据；缺项明确写未验证。

这份是内部接入说明，不发布给客户。现有 A 内文档可作为来源，但日期旧、声称完全兼容或未覆盖异步的部分必须对照代码修正；不能原样当公开契约。避免手抄全项目无关文档。

## 3. 研究与配置：research/newapi-integration.md、newapi/<能力ID>/channel.md

研究记录按 research-newapi.md，解释为什么直接接入、复用/自定义插件或独立适配，给当前版本依据、差异、未知项与必要用户决定。

channel.md 按 channel-config.md，给实际绑定/路由/分组/计费配置和秘密位置、配套服务、部署和回退。新渠道未部署时提供明确配置差异，不能虚构 ID/已启用版本。

## 4. 实际接入代码与测试

任务插件：plugin.js 与真实转换/状态/产物/用量测试；独立服务：adapter/ 中源码/配置/部署与测试；内置适配直接接入：配置和契约/调用验证即可，不强行新建 plugin.js。

接入代码放对应源工程的目录，所有 A 共享的代码另有明确归属，不复制出多个活跃版本。业务功能仍在 A；独立伴随服务仍在 A 时记录位置和依赖，未迁移部署不能写成已迁移。

## 5. 客户公开文件：同一能力目录四个文件

public-openapi.json 描述客户经过 B 的实际接口；public-guide.zh.md/en.md 描述流程、限制、选型和费用语义；public-docs.json 是能力版本/分类/模型/公开文件路径清单。

清单路径相对 C 根目录，例如：
projects/vidu2api/newapi/media-image/public-openapi.json

规范 OpenAPI 3.1、版本与清单一致、稳定 operationId、内嵌 $ref、中英文标题/说明、真实错误和示例。分类/模型展示见 ../maintenance/model-catalog-contract.md。同协议多渠道复用一个公共契约；新渠道的项目 README 指向该契约维护位置。需要不同客户行为时先确定独立 ID，不能重复登记 ID覆盖现有目录。

客户指南应提供可独立运行的最小例子，使用客户 Key 占位符；异步含查询和获取产物，stream 含完整事件/结束处理。价格只写已验证公开售价/查询方式，内部成本不公开。

只将四个公开文件列入清单。项目身份、上游、研究、channel、密钥和原始证据均不导入客户网站。OpenAPI 与文档不是功能实现，必须通过真实适配器和客户入口核对。

## 6. 验收与状态：releases/<能力ID>/<版本>.md

使用 templates/api-release-handoff.md，保存 A 运行版本、B 已启用插件/渠道与哈希、真实客户业务/错误/长任务和账单、公开契约版本、C 文档部署结果。

源码/配置可用、B 已启用、客户已验收、C 已发布分别记录。只有插件源码哈希一致不证明价格/配套服务也正确。迁入旧证据注明原日期，不能写成本次重跑。

C 在仓库根执行 npm test、npm run docs:sync、npm run build、npm run docs:check。当前 npm test 会运行 projects/*/newapi/ 下既有适配测试；新增服务测试按实际语言接入命令或记录明确运行方式。自动测试不能写 B 配置或创建付费任务。

## C 写好 DOC 站需要什么

C 首先读 projects/<源工程ID>/README.md，而不是遍历 A 所有文件或猜聊天历史。收到：
- 项目身份和 A 版本，知道由哪个工程实现、谁负责维护。
- 上游说明和协议差异，理解为什么有扩展字段与限制。
- 客户规范与同版本中英文指南，直接生成文档，无需再手填参数。
- 真实渠道/计费/部署验收记录，判断能否公开称可用。
- 分类、模型差异/操作、计费单位、错误与排查、完整客户示例，生成选型、模型中心和 FAQ。

内部说明补充上下文，客户参数表以实际客户契约为准。关键材料缺失时 C 向对应项目作者指出具体缺项，不能自己猜；可继续本地预览但不发布未验证能力。

所有源工程入口在 ../../projects/README.md。本次为 projects/vidu2api/；其他未登记项目不视为已交付。
